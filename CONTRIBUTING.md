# Правила командной работы (CONTRIBUTING.md)

## 1. Ветки (Branches)
- Основная ветка: `main` (защищена от прямого пуша).
- Тематические ветки создаются от `main` и именуются по шаблону: 
  - `docs/uc-02-trade` (для документов)
  - `fix/report-typo` (для исправлений)
  - `feature/...` (для кода в будущем)

## 2. Коммиты
- Один коммит = одно логическое изменение.
- Сообщение коммита на русском языке, описывает результат, а не процесс. 
  - Хорошо: «Добавлен альтернативный поток A1 для UC-02»
  - Плохо: «обновление», «правки», «123»

## 3. Запросы на слияние (Pull Requests)
- Все изменения в `main` вливаются **только** через Pull Request (PR) на GitHub.
- В описании PR укажите: цель изменения, связанные ФТ/UC, скриншоты (если есть).
- Проверку (Review) проводит **другой** участник команды, не автор изменений.
- Слияние выполняется только после одобрения (Approve) и успешного прохождения проверок.

## 4. Правило актуальности документов
- Основной редактируемый формат отчётов — **Markdown** (`.md`).
- Word-версии (`.docx`) обновляются **после** согласования Markdown и непосредственно перед сдачей преподавателю.
- Исходник диаграммы (`.puml` / `.drawio`) и её изображение (`.png`) обновляются **в одном коммите**.
- Правки содержания напрямую в `.docx` запрещены (только исправления оформления).

## 5. Исключаемые файлы (.gitignore)
В репозитории не должны находиться:
- Временные файлы Word (`~$*.docx`)
- Системные файлы (`Thumbs.db`, `.DS_Store`)
- Локальные настройки IDE (`.vscode/`, `.idea/`)
